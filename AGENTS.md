# Инструкции для работы с Sites Nodes

- Общайся с пользователем на русском языке. Страницы эталона Stayroute остаются на английском; для новой локации язык меняется только по заданию пользователя.
- Сначала прочитай корневой README.md, затем документы выбранного образца. Не применяй инструкции другого образца случайно.
- `sites/stayroute-nyc` — эталон **Stayroute NYC — City Guide**, идентификатор `stayroute-nyc`. Его можно полностью скопировать как основу сайта другой локации. Для адаптации создавай новый каталог/рабочую копию, сохраняя эталон.
- Под запросом «такой же сайт» понимай сохранение визуального оформления и поведения: страницы, сетки, палитра, типографика, карты, прогулки, избранное, смена времени суток. Не заменяй готовый дизайн другим и не добавляй обязательный backend.
- Под новую локацию проверяй весь контент: географию, часовой пояс, солнечные координаты, погоду, изображения, статьи, ссылки и подписи. Одной замены названия города недостаточно.
- Маршруты рассчитывай настоящим пешеходным профилем и сохраняй локально с источниками. Прямые линии между точками не выдавай за маршруты по улицам. Непроверенные участки и ограничения сообщай прямо.
- Соблюдай лицензии и атрибуцию OSM и других источников. У эталона нет флага/подписи Leaflet в интерфейсе; обязательная атрибуция OpenStreetMap сохранена.
- Изменения сайта не дают полномочия менять веб-сервер, средства доступа, сокеты, контейнеры, службы, TLS, брандмауэр или сетевые настройки. Не вноси такие изменения без прямого задания.
- Не публикуй новую локацию на действующей ноде без прямого запроса. Если публикация запрошена, сначала подготовь и проверь результат, сравни текущие файлы, сделай резервную копию и затем выполни разрешённый перенос.
- При добавлении нового образца обнови таблицу корневого README.md, добавь имя, идентификатор, описание и инструкции для следующего Codex.

## Конфиденциальность перед публикацией

- Домены и поддомены действующих сайтов, адреса нод, IP, внутренние пути сервера, контакты и сведения о размещении считаются конфиденциальными. Не публикуй их без отдельного прямого разрешения. Разрешение загрузить исходники в GitHub само по себе не разрешает публиковать сведения об инфраструктуре.
- В публичных примерах используй локальный просмотр либо нейтральные заглушки. Перед коммитом проверь README, метаданные, скрипты, заголовки запросов, примеры, изображения, архивы и историю. Не публикуй резервные копии, журналы сервера и секреты.
